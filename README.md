# Toronto CRM

CRM для уборки снега: колл-центр принимает заявки и назначает водителей, водитель ведёт заявку с телефона.
Минималистичный чёрно-белый интерфейс на русском языке, как у Agora CRM.

## Роли

| Роль | Что может |
|---|---|
| **Quant** | Всё. Только Quant добавляет сотрудников, меняет им роль, пароль и отключает доступ. Журнал входов. |
| **КЦ (оператор)** | Создаёт заявки и назначает водителя, меняет и отменяет их, видит «Свободны / заняты», список сотрудников с ролями и отчёт. |
| **Уборщик снега** | Видит только свои заявки. Роли и других сотрудников не видит. |

## Заявка

КЦ заполняет: 0) имя и телефон клиента, 1) адрес (или ссылку на карту), 2) во сколько приехать,
3) сколько платит клиент и как (наличные / трансфер), 4) сколько получит работник, 5) задачу,
6) по прибытии позвонить клиенту или сразу приступать. И выбирает водителя.

Путь водителя:

1. **Принять** — сразу открывается навигатор (Google Карты) до адреса. На странице остаются кнопки «Открыть навигатор» и «Waze».
2. **На месте** — если клиента нужно оповестить, крупная кнопка **Позвонить клиенту** (и под ней «Начать»), иначе сразу **Начать**.
3. **Закончено, оплачено** — после работы и получения оплаты.

Пока у водителя есть назначенная и не закрытая заявка, он в разделе **«Заняты»**, иначе — **«Свободны»**
(главная КЦ и меню «Свободны / заняты»). Если КЦ отменит заявку или переназначит её, водитель освобождается.
Страница водителя без заявки в работе обновляется сама каждые 30 секунд, чтобы новая заявка появилась без перезагрузки.

### Геолокация работников и системное предложение

Местоположение берётся только у работников (роль «Уборщик снега») и только пока они **в сети**. Постоянно оно не отслеживается:
телефон присылает точку, когда CRM её попросила, — при создании заявки (системное предложение), когда КЦ / Веб / Quant открывают
заявку, при выходе в сеть и при нажатии «Принять». При выходе из сети точка стирается.

- **Системное предложение** (форма заявки, после ввода адреса): работник в сети с наименьшим числом незакрытых заявок
  (среди равных — кто ближе к концу текущей), затем ближайший по времени в пути. Если водитель ещё не выбран, предложение подставляется само.
- **Заявка**: «Где работник» — расстояние и минуты до адреса; когда работник едет — «примерно N мин до адреса клиента».
- Работнику нужно разрешить геолокацию в браузере (плашка на его главной) и держать CRM открытой: браузер отдаёт местоположение
  только открытой странице. Если работник в навигаторе, используется последняя точка (например, с момента «Принять»), а минуты в пути от неё вычитаются.
- Адрес → координаты: OpenStreetMap Nominatim (кэш в таблице `geocodes`), время в пути: OSRM, без учёта пробок.
  Если сервис маршрутов недоступен — оценка по прямой.

**Дом по адресу** (форма заявки): спутниковый снимок сверху (Esri World Imagery, без ключа) и кнопка Google Street View.
Чтобы Street View показывался прямо в форме, добавьте в Cloudflare секрет `GOOGLE_MAPS_EMBED_KEY` — ключ Google Maps Embed API
(бесплатный; в Google Cloud ограничьте ключ адресом сайта CRM).

Время — по Торонто. Отчёт за период: сколько заявок выполнил каждый водитель, наличные / трансфер, доля работника, ваш доход
и сколько наличных водитель должен сдать (он оставляет себе из наличных и долю с заявок по переводу).

Нажмите на имя водителя в отчёте или в «Сотрудниках», чтобы открыть его профиль с заявками, наличные по которым ещё не сданы.
Quant и Веб отмечают «Вся сумма покрыта» или галочками выбирают заявки, деньги по которым ещё не переданы (остальные считаются сданными).
Внизу история: когда и кто отметил, с кнопкой «Отменить». В отчёте «Сдать наличных» считает только несданное.

## Где работает

Сайт работает на **Cloudflare Workers**, данные — в базе **Cloudflare D1**. Таблицы и учётная запись Quant
создаются автоматически при первом открытии сайта. Пароль Quant в коде хранится только в виде хэша.
После первого входа пароль можно сменить: меню «Мой пароль».

### Подключение к Cloudflare (один раз)

1. Cloudflare → Workers & Pages → Create → **Import a repository** → выбрать `quant-develope/Toronto-CRM`.
2. Build command — пусто, Deploy command — `npx wrangler deploy`, ветка — `main`.
3. Deploy. Базу D1 `toronto-crm` Cloudflare создаст сам при первом деплое.

После этого каждое слияние в `main` обновляет сайт само.

Если деплой пишет, что база не найдена: Cloudflare → Storage & Databases → D1 → Create, имя `toronto-crm`,
и впишите её Database ID в `wrangler.jsonc` (`"database_id": "…"` рядом с `database_name`).

## Запуск на своём компьютере

Нужен Node.js 20+.

```bash
npm install
npm run dev
```

Сайт откроется на http://localhost:8787 с локальной копией базы (в папке `.wrangler/`).

## Приложение на телефоне и компьютере (PWA)

Сайт ставится как приложение. Chrome/Edge на компьютере: кнопка «Установить» внизу меню. Android: меню браузера → «Установить приложение».
iPhone: в Safari «Поделиться» → «На экран „Домой“». Иконка снежинки, открывается без адресной строки.

На компьютере (экран от 1024 px) меню всегда слева, у КЦ рядом с формой заявки видно свободных и занятых водителей,
на главной — водители и ближайшие заявки. Быстрые клавиши: N — новая заявка, Z — заявки, D — свободны / заняты.

## Уведомления

- Quant и КЦ получают уведомление, когда водитель меняет статус заявки (принял, на месте, начал, закончил).
- Водитель получает уведомление, когда ему назначают заявку.

Когда CRM открыта, уведомление появляется в правом верхнем углу. Чтобы получать их на телефон или компьютер, когда сайт закрыт,
нажмите в меню «Включить уведомления» на каждом устройстве. На iPhone push работает, только если CRM открыта с экрана «Домой»
(iOS 16.4+). Ключи для push создаются сами при первом запуске, настраивать ничего не нужно.

## Телефония (Twilio)

Клиент звонит на торонтовский номер → в CRM у Quant и КЦ всплывает уведомление «📞 Звонок +1 416 …» (и push на телефон).
Нажатие на уведомление открывает новую заявку с уже подставленным номером; если клиент звонил раньше, подставляются его имя и адрес.
Все звонки — в меню **«Звонки»**: принятые, пропущенные (кнопка «Перезвонили») и кнопка «Создать заявку».

Звонок переадресуется на телефоны операторов из раздела «Звонки» → «Переадресация» (меняет Quant): звонят все сразу,
у оператора на экране номер клиента. Если никто не ответил за 25 секунд или номеров нет, клиенту говорят, что ему перезвонят,
а звонок попадает в пропущенные.

### Подключение (один раз)

1. twilio.com → зарегистрироваться → Phone Numbers → Buy a number → Canada, код 416, 647 или 437, с галочкой Voice.
2. Cloudflare → Workers & Pages → `crm-toronto1` → Settings → Variables and Secrets → Add → тип **Secret**,
   имя `TWILIO_AUTH_TOKEN`, значение — Auth Token из главной страницы Twilio Console. Секрет не пропадает при следующих деплоях.
3. Twilio → Phone Numbers → Active numbers → ваш номер → Voice Configuration:
   - A call comes in: **Webhook**, `https://<адрес CRM>/twilio/voice`, HTTP POST;
   - Call status changes: `https://<адрес CRM>/twilio/status`, HTTP POST.
4. В CRM: «Звонки» → «Переадресация» → телефоны операторов через запятую.

Запросы на `/twilio/*` принимаются только с верной подписью Twilio (X-Twilio-Signature), без секрета они отклоняются.

**SignalWire вместо Twilio** (если у Twilio нет номера): signalwire.com → Phone Numbers → Buy → Canada, 416/647/437.
В Cloudflare вместо `TWILIO_AUTH_TOKEN` добавьте секрет `SIGNALWIRE_SIGNING_KEY` (API → Signing Key). В настройках номера:
Handle calls using **LaML Webhooks**, When a call comes in — `https://<адрес CRM>/twilio/voice`, Status change webhook — `https://<адрес CRM>/twilio/status`.

## Заявки с сайтов

Форма «Get a free quote» на сайтах (сейчас — snowman-toronto) дублирует заявку в CRM. Она появляется в меню **«Звонки»**
со статусом «Заявка с сайта — позвонить», с названием сайта и тем, что клиент написал (услуга, размер участка, комментарий, реклама).
Quant и КЦ получают уведомление «🌐 Заявка с сайта», нажатие открывает новую заявку с подставленными именем, телефоном, адресом и задачей.
Клиент заводится в «Клиентах» и закрепляется за тем, кто ведёт сайт с этим номером («Сайты»). После звонка — «Перезвонили» или «Создать заявку».

Сайты передают заявку через service binding к этому Worker (entrypoint `SiteLeads`, метод `siteLead`), а не через открытый адрес,
поэтому секретов не нужно. В `wrangler.jsonc` сайта:
`"services": [{ "binding": "CRM", "service": "crm-toronto1", "entrypoint": "SiteLeads" }]`, затем `await env.CRM.siteLead({ name, phone, address, city, service, … , site, site_phone })`.

## Клиенты

Меню «Клиенты» — база клиентов. Клиент заводится сам: при звонке на номер телефонии или при создании заявки (клиента узнаём по последним 10 цифрам номера).

- **Оператор клиента** — тот, на чей номер клиент позвонил («Звонки» → «Номера и операторы»; если номера там нет — кто ведёт сайт с этим номером).
  Звонок на номер оператора идёт на его личный телефон из карточки сотрудника. Если клиент пришёл не по звонку — оператор тот, кто создал его первую заявку.
- **Работал с нами** — есть выполненная заявка. **Закрыл** — кто создал первую выполненную заявку (может быть другой оператор).
- Менять данные клиента могут Quant и оператор клиента; оператора клиента меняет только Quant.
- Кнопка **WhatsApp** у клиента, в звонках и в заявке открывает чат с клиентом.

### OpenPhone (Quo)

Звонки и SMS с номеров OpenPhone тоже попадают в «Звонки» (с пометкой «OpenPhone»), клиенты — в базу.
1. OpenPhone → Settings → Integrations → Webhooks → Create webhook: URL `https://<адрес CRM>/openphone/webhook`,
   события call.ringing, call.completed, call.recording.completed, call.transcript.completed, message.received.
2. В webhook → ⋯ → Reveal signing secret → скопировать → Cloudflare → `crm-toronto1` → Variables and Secrets → Secret `OPENPHONE_WEBHOOK_SECRET`.
3. Номера OpenPhone привязать к операторам в «Звонки» → «Номера и операторы».
4. Прошлые звонки: Quo → Settings → API → ключ → Cloudflare Secret `QUO_API_KEY`, затем «Звонки» → «Загрузить звонки из Quo»
   (порциями, нажимать до «Загружено всё»). С этим ключом «▶ запись» сама находит запись звонка в Quo.
